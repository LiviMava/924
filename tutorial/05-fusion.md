# 05 · RRF 融合：把两份排名合成一份

关键词与向量召回会得到不同候选，也会同时找到同一片段。融合根据片段 ID 合并两路结果，保留双方的排名信息，得到用于模型重排的候选列表。

## 运行与输入

```powershell
.\tutorial\demos\05-fusion.ps1 -Query '去上海出差，酒店每晚最高能报销多少钱？'
# 离线对照：只有关键词一路，向量贡献为 0
.\tutorial\demos\05-fusion.ps1 -RecallMode keyword
```

网页第 04 步先运行双路召回，第 05 步选择融合后保留数量。输入是同一个问题、两份实际候选和 Top-K；本步不调用模型。输出展示去重后的数量、每路名次及贡献、RRF 总分和片段原文。[实测输入输出](outputs/hybrid/fusion.json)

## 原理与手算

```text
RRF(chunk) = 1 / (60 + 关键词名次) + 1 / (60 + 向量名次)
缺席某一路时，那一路贡献为 0；名次从 1 开始。
```

假设关键词第一是 A，第二是 C；向量第一是 B，第二也是 C：

| 片段 | 关键词名次 | 向量名次 | RRF |
|---|---|---|---|
| C | 2 | 2 | 1/62 + 1/62 ≈ 0.032258 |
| A | 1 | 缺席 | 1/61 ≈ 0.016393 |
| B | 缺席 | 1 | 1/61 ≈ 0.016393 |

C 得到两路支持而排到前面。这个表是公式讲解；网页和 JSON 展示实际检索结果，不要求每次都出现这个排序。

BM25 与 Cosine 的分数尺度不同，RRF 用名次避免直接相加。融合分数体现排名支持程度，不是模型对语义的判断，也不是答案正确率。它可能把泛泛相关的片段排到前列，下一步仍需要重排和原文核对。

教程复用生产 `ReciprocalRankFusion.fuse()`，常数为 60；同一分支重复 ID 不重复加票、不占额外名次，两路重复片段只保留一条。同分按片段 ID 稳定排序。每条输出保留 `keywordRank/vectorRank`、原始分支分数、`keywordContribution/vectorContribution/fusedScore`，可以手算核验。

修改问题、阈值、分块或召回模式后重新召回，旧融合、重排、Prompt 与回答都会失效。融合后减少候选数量可能删除正确证据，因此要观察候选是否仍覆盖答案。
